# แผนพัฒนาระบบรับสินค้าและสต๊อกด้วย QR Code

## เป้าหมาย
ต่อยอดจากเว็บเดิมบน GitHub Pages โดยรักษาฟังก์ชันเดิมไว้ และเพิ่มระบบจัดการสินค้า/สต๊อกที่ใช้งานได้ทั้งมือถือและคอมพิวเตอร์

## QR Code สองประเภท
1. **QR สินค้า (PRODUCT)** — ผูกกับรหัสสินค้าถาวร เมื่อตรวจพบให้ผู้ใช้กรอกจำนวนและหน่วยเอง
2. **QR ลัง/แพ็ก (PACKAGE)** — ผูกกับรหัสแพ็กที่ไม่ซ้ำกัน ระบุสินค้า จำนวนต่อแพ็ก และหน่วยไว้ล่วงหน้า เมื่อสแกนให้แสดงรายละเอียดและจำนวนที่จะรับเข้า ผู้ใช้ยืนยันก่อนบันทึก

ตัวอย่าง:
- สินค้า: P001 / มะเขือเทศ / หน่วยหลัก กก.
- QR สินค้า: PRODUCT:P001
- QR ลัง: PACKAGE:BOX-P001-001 / P001 / 20 กก.

## หน้าจอหลัก
- แดชบอร์ด: ยอดสินค้า จำนวนคงเหลือ และรายการเคลื่อนไหวล่าสุด
- สแกน QR: ใช้กล้องมือถือหรือกล้องเว็บแคม และมีช่องกรอกรหัสสำรอง
- รับสินค้าเข้า: สแกนสินค้าแล้วกรอกจำนวน หรือสแกนแพ็กแล้วใช้จำนวนที่กำหนด
- จ่าย/เบิกสินค้า: ระบุจำนวนและเหตุผล
- สินค้า: เพิ่ม แก้ไข ค้นหา และพิมพ์ QR ประจำสินค้า
- ลัง/แพ็ก: สร้างรหัสเฉพาะ กำหนดจำนวนต่อแพ็ก และพิมพ์ QR
- ประวัติ: ค้นหาตามวันที่ สินค้า ประเภทการเคลื่อนไหว และผู้ทำรายการ
- รายงาน: สรุปยอดรับเข้า จ่ายออก และคงเหลือ
- ผู้ใช้และสิทธิ์: เจ้าของ/ผู้ดูแล/พนักงาน

## โครงสร้างข้อมูลที่เสนอ
- Products: product_id, sku, name, base_unit, active
- Packages: package_id, product_id, package_label, quantity, unit, status
- QR_Codes: qr_id, qr_type, target_id, active
- Stock: product_id, quantity_on_hand, updated_at
- Transactions: transaction_id, type, product_id, quantity, unit, source_qr_id, package_id, note, user_id, created_at
- Users: user_id, display_name, role, active

## กติกาความถูกต้องของสต๊อก
- ทุกการรับ/จ่ายต้องสร้างประวัติรายการเคลื่อนไหว
- ห้ามจ่ายจนยอดติดลบ เว้นแต่เจ้าของเปิดสิทธิ์
- การสแกน QR ลังซ้ำต้องตรวจสอบสถานะ/ประวัติและเตือนก่อนรับซ้ำ
- การบันทึกต้องมีรหัส transaction ไม่ซ้ำ เพื่อป้องกันการกดซ้ำ
- QR แพ็กต้องยืนยันสินค้า จำนวน และหน่วยก่อนบันทึก
- รองรับการแก้ไขย้อนหลังโดยสร้างรายการปรับปรุงอ้างอิงรายการเดิม ไม่ลบประวัติเดิมทิ้ง

## สถาปัตยกรรม
- Frontend: เว็บแอป responsive / PWA บน GitHub Pages
- Backend: ต้องตรวจสอบระบบเดิมก่อนเลือกว่าจะใช้ Google Apps Script หรือบริการฐานข้อมูลเดิม
- Database: เลือกแหล่งข้อมูลกลางหลังตรวจสอบไฟล์และการเชื่อมต่อเดิม เพื่อให้มือถือและคอมพิวเตอร์เห็นข้อมูลชุดเดียวกัน
- Scanner: ใช้กล้องเมื่อเบราว์เซอร์อนุญาตและหน้าเว็บทำงานผ่าน HTTPS พร้อมช่องกรอกรหัสเป็นทางเลือก

## ลำดับการพัฒนา
1. ตรวจสอบโค้ดเดิมและรูปแบบข้อมูลจริง (ห้ามเขียนทับโดยไม่สำรอง)
2. สร้างหน้าจอและระบบสินค้า/QR สองประเภท
3. เชื่อมฐานข้อมูลกลางและระบบรับ/จ่ายพร้อมป้องกันรายการซ้ำ
4. เพิ่มประวัติ รายงาน และสิทธิ์ผู้ใช้
5. ทดสอบบนมือถือและคอมพิวเตอร์ ก่อนเผยแพร่

## ข้อควรระวัง
เอกสารนี้เป็นข้อกำหนดเริ่มต้น ยังไม่ถือว่าระบบฐานข้อมูลหรือการสแกนใช้งานจริงเสร็จแล้ว ต้องตรวจสอบไฟล์ backend และข้อมูลเดิมก่อนเลือกวิธีเชื่อมต่อและย้ายข้อมูล
